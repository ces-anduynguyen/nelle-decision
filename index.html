The principle behind every case: your row only sees your own records

The principle

The list builds your row from your own records only, and it does that first. Only then does it look for the newest round. So a newer round that belongs to someone else can never replace your old one.

Only your records

The list keeps only the rows where you are the requester (“My requests”) or the approver (“Assigned to me”).

Explains CR-P4 · CR-P5 · DoA-P5. Each person sees only their own slice of the document.

The newest round is picked too late

It looks for the newest round per topic only among the rows it already kept. If the newer round is B's, A's list never sees it.

Explains CR-P1 · CR-P2 · DoA-P2. Old approvers stay frozen at their own verdict.

Only undecided records get replaced

A new version marks rounds that are still pending as STALE. Decided rounds are never replaced. The Approval list hides STALE rows. The DoA list does not.

Explains CR-P3 (hidden, unlike CR-P1/P2) · DoA-P1 (shown as Stale, unlike CR-P3).

See it on CR-P1, from A's list:

⚠ Today

  1. Keep only rows where the approver is A.
  2. Pick the newest round for each topic.
  3. A only has round 1, so round 1 counts as “newest”. A sees ✕ Rejected.

✓ Fix (option 2, chosen)

  1. Find the newest round for each topic, across everyone.
  2. Then keep A's rows. Mark any that are not the newest as Stale.
  3. A's round 1 is older than B's round 2, so A sees ⌛ Stale.

Both options start the same way: find the current round for everyone first. Option 2 then shows your older rows as Stale. Option 1 would hide them instead.

Every case, step by step

Pick one rule, use it for Approval and DoA

Option 1 · Hide rows that are no longer current

What A sees in CR-P1
The document leaves A's list. A's rejection still shows in the detail page, under Previous rounds.
Why
The list becomes “work you can act on now”. It matches the detail page and the “live work only” choice already made in 86e2gqpup. CR-P1 and CR-P2 start behaving like CR-P3, which already hides the row.
Work
Small. Change two queries, no API or UI change.
✓ Chosen

Option 2 · Keep the row, show it as Stale

What A sees in CR-P1
The row stays, with the status ⌛ Stale. A's rejection still shows in the detail page, under Previous rounds.
Why
One rule for both lists. Old approvers can still find documents they touched. No row claims a verdict that is no longer true. DoA-P1 already works this way.
Work
Medium. Both list queries find the current record first, then mark the viewer's older ones as Stale. The Approval detail page lets past participants in, like DoA already does. No new API field: both UIs can already show “Stale”.
⚠ Watch out
  1. “Stale” would mean two things. Today it means “replaced before anyone decided”. Work it out in the list. Never write STALE over an Approved or Rejected record, or the verdict is lost.
  2. Approval rows: replaced rounds don't count toward the status or the topic count. The row shows Stale only when all of that person's topics were replaced.
  3. The Approval detail page drops STALE rounds and gives a 404 to people who only have one. It must show them under Previous rounds and let those people in, like DoA.
  4. This reverses the “live work only” choice in 86e2gqpup. Agree it with the ticket author.
  5. Stale rows pile up. Hide Stale by default in the status filter, and keep it pickable.

Option 3 · Label “your part only” (add-on)

What it fixes
CR-P4 and CR-P5. Approver rows only cover their own topics. Neither option 1 nor 2 changes that.
Idea
A small hint on approver rows, like ℹ Your topics only.
Work
Small UI-only change. Can ship with 1 or 2.
